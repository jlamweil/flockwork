## What the dogfood caught (the point of the run)

1. **`sh()` didn't accept `env=`** — dispatch kwarg crash, caught by
   example-host-c and example-host-b simultaneously (same shared code, two hosts, both
   honest verdict rows). The two-host claim+crash cycle exercised the
   sweep law for real, twice.
2. **Nodes must pull, never scp** — the example-host-b node ran a stale pre-fix
   inrepo.py from an scp drop (c9-era reflex). Fix: sync via
   fetch+reset from the origin. Lesson encoded: code ships THROUGH the
   substrate.
3. **Zombie TUI defeats pgrep gates** — a defunct freebuff process
   matches pgrep and answers kill(pid,0); the stale owner-file gate
   must be unconditional. (fbconn campaign's pid_alive lesson, now
   encoded in the dispatch.)
4. **Remote active sessions cannot be displaced** — the freebuff
   dispatch failed 6 attempts across example-host-d and example-host-c with
   SingletonBusy (active session = THIS conversation's runtime; no
   idle window existed while the loop streamed). Verdict: freebuff is
   an **idle-window-gated backend**, not always-on. T3 re-dispatched
   via opencode and fixed in one clean pass.
5. **Audit must read bodies on the origin host** — local cat-file is
   blind to objects pushed after the auditor's last fetch (empty body
   → IndexError). Now remote-host reads.

## Postscript — night hardening round (2026-09-18, night session)

The six environmental deaths above were recovered by MANUAL sweep
invocations — the T4 sweep primitive existed, but nothing detected
*what* to sweep (the SILENT-STALE shape DESIGN-NEXT §2.3 warns about).
This round closes that gap in `l2/inrepo.py`:

1. **`reconcile [ORIGIN] [TTL_S]`** — automated stale-claim recovery:
   a live claim older than the lease TTL (default 1800 s,
   `SWARM_LEASE_TTL`) whose task lacks live return+verdict is
   archived+freed by the T4 sweep (one atomic push), so the task
   re-enters `open_tasks`. Safety is by construction, not timing:
   return/verdict refs are create-once CAS (L2), so even a mis-timed
   sweep of a live worker costs a duplicate attempt, never a double
   verdict. Never swept: healthy tasks, fresh claims, and shapes that
   should not exist or cannot be dated (orphan return/verdict refs,
   undateable claim objects) — flagged for the auditor instead.
   Age is the claim commit's committer date, read on the ORIGIN host
   (`origin_commit_ts`; the T5 law generalized from bodies to headers).
2. **Dispatch-classified verdicts** — verdict bodies now carry
   `oc_rc:`/`pytest_rc:` so the error table applies from the refs
   alone (timeout 124 → environmental/requeue; 0 with pytest fail →
   merit). Old verdicts (no oc_rc) parse unchanged — verified live.

reconcile + 3 verdict-classification, local bare origins, no fleet);
live on the example-host-a origin: audit h1_pass true (all five tasks,
atts matching), reconcile reports all five healthy and sweeps nothing,

## Postscript 2 — the c6 error policy becomes code (same night)

The frozen c6 rule ("environmental death = no commit ∧ no patch → one
heir attempt max; merit failure final") lived in FREEZE.md prose only:
the loop recorded environmental deaths as final `fixed:false` verdicts,
permanently closing the task, and an unreachable origin made a worker
exit silently looking like "queue empty". Now enforced in `work_task`/
`worker` (commit 91db62a):

1. **Env-death requeue, in-run.** A dispatch that failed leaving no
   work in the tree (timeout 124; exit≠0 with empty tree — the
   model/provider-death shape; clone failure) archives the dead attempt
   and frees the claim in the SAME run (T4 sweep) — no reconcile TTL
   wait — so the task re-enters `open_tasks` immediately. Heirs are
   bounded: with a dead attempt already archived, the honest
   `fixed:false` verdict (oc_rc records why) is FINAL. Merit failures
   (dispatch completed, oracle failed) were always final.
2. **An env death is never a fix.** On the heir-exhausted path the
   oracle can trivially pass on an unchanged tree — `fixed` now
   requires the oracle AND a live dispatch (caught by the contract
   test before ever touching the fleet).
3. **Honest worker lifecycle.** `open_tasks` raises on an unreachable
   origin (queue-empty ≠ cannot-see-the-queue); the worker retries,
   then gives up with `worker_gave_up` + exit 1 after
   SWARM_WORKER_MAX_FAILS (default 3) consecutive dead scans; a
   per-task exception never kills the loop holding its claim — the
   attempt is recorded and the claim freed best-effort.

Evidence: 8 new contract tests driven through the REAL `work_task` in
subprocesses (stub dispatch binaries, local bare origins — no fleet,
no model): timeout-requeue, exit-3-requeue, merit-final,
heir-exhausted-final, success-with-trailer, unreachable-origin raise,
worker give-up (exit 1), clean queue-empty exit. Suite 52/52; live
origin unchanged (audit h1 true, five healthy, nothing swept).
