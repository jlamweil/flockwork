## What the dogfood caught (the point of the run)

1. **`sh()` didn't accept `env=`** — dispatch kwarg crash, caught by
   example-host-c and example-host-b simultaneously (same shared code, two hosts, both
   honest verdict rows). The two-host claim+crash cycle exercised the
   sweep law for real, twice.
2. **Nodes must pull, never scp** — the example-host-b node ran a stale pre-fix
   inrepo.py from an scp drop (c9-era reflex). Fix: sync via
   fetch+reset from the origin. Lesson encoded: code ships THROUGH the
   substrate.
3. **Zombie TUI defeats pgrep gates** — a defunct freebuff process
   matches pgrep and answers kill(pid,0); the stale owner-file gate
   must be unconditional. (fbconn campaign's pid_alive lesson, now
   encoded in the dispatch.)
4. **Remote active sessions cannot be displaced** — the freebuff
   dispatch failed 6 attempts across example-host-d and example-host-c with
   SingletonBusy (active session = THIS conversation's runtime; no
   idle window existed while the loop streamed). Verdict: freebuff is
   an **idle-window-gated backend**, not always-on. T3 re-dispatched
   via opencode and fixed in one clean pass.
5. **Audit must read bodies on the origin host** — local cat-file is
   blind to objects pushed after the auditor's last fetch (empty body
   → IndexError). Now remote-host reads.

Final: h1_pass TRUE, 5/5 verdicts true, contract suites 7/7 on delivered main.

### Findings (all encoded)
1. **Model-size must fit task-size**: flash timed out twice at 420-600s on T4; gemini-2.5-pro
   needed ~9 min. Encoded: `SWARM_DISPATCH_TIMEOUT` (default 600).
2. **Provider outages are environmental, not merit**: example-host-c hpc-glm socket-failed twice,
   recovered ~20 min later. Two consecutive env verdicts -> probe provider directly.
3. **Operator tests fail for operator reasons**: T5's three false verdicts were (a) fixture
   not full-protocol (claim only; h1 needs return+verdict), (b) `rindex("{")` vs pretty JSON,
   (c) in-process env-swap after import-time `ORIGIN` bind (audits the wrong repo vacuously).
   The lane held: workers honestly recorded `fixed:false`; nobody "passed" a broken test.
4. **Arg-label trap**: `inrepo.py worker T5-...` treats the task name as a LABEL
   (`argv[3:]` = filter, `argv[2]` = worker label). Untargeted workers claim sorted-first.
   Caused a claim swap; harmless (att is the real identity) but document before anyone
   "fixes" it into a bug.
5. **Incomplete sweep leaves zombie returns**: sweeping claim+verdict but not the return
   ref makes a task permanently invisible to `open_tasks`. Sweep must be all-or-nothing —
   now the T4 contract's job, permanently.
6. **example-host-b had NO git remote** (scp-era seeding): "nodes pull" was never wired there.
   Fixed permanently: `git remote add origin ssh://example-host-a/...` + reset-hard relaunch.
   Transient example-host-a->example-host-b ssh 255s also observed (retry, don't re-diagnose).
7. **Concurrent lane-code edits collide on main** (conflict during T5's return push):
   resolved manually; batches should partition files or accept rebase discipline.
