## Wave 5 (22:3x–23:1x, INT-013 sitting 5): refusal/death flows pinned;
## phantom-verdict bug found and closed

Preregistration: pin the wave-4 claim as executable contracts — (1) a
GUARDED takeover refusal is an honest env death (dispatch_error, oc_rc
1, in-run requeue), final when the heir budget is spent, and never
kills or touches the owner file; (2) the quiet no-text death
(transcript never opened) requeues on an empty tree and is merit-final
with partial work. Hermetic: mode-switching stub fbconn, throwaway
HOME, recording pkill.

The red runs exposed a REAL latent bug, not a test artifact: every
claim/verdict/spec write used AMBIENT git identity. From an
identity-less node (first reached by the throwaway-HOME harness;
exactly a fresh worker node's shape) `commit-tree` fails rc 128 and
the EMPTY sha flowed into `<empty>:refs/swarm/verdicts/<task>` — an
empty-source refspec git treats as a ref DELETION and exits 0, so the
event reported `verdict_pushed: true` with NO verdict ever written.
All prior green runs inherited the developer's $HOME; the phantom was
invisible.

Fix (`l2/inrepo.py`): every commit-tree site now carries a
deterministic lane identity (-c user.email/user.name), and
`commit_tree()`/`push_sha_ref()` guarantee a failed commit NEVER
becomes a push — the failed commit's own proc (real rc/stderr) flows
to the caller, preserving the classifier contract in test_claim_loss
(structural claim failures keep surfacing rc 128 "not a git
repository"). Conversion defects made during the edit (twice-dropped
tree arg, one merged line) were each caught by the suite and repaired
in-place — the suite is the falsifier it is meant to be.
