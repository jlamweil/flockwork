## Finding (code-read + measured)

Two ssh-exec sites build remote commands from REMOTE-DATA refnames
unquoted:

1. `origin_raw` (cat-file on the origin host) — reachable from
   `sweep` att-recovery, `reconcile` dating, `relabel`, `audit` body
   reads: all consume `ls-remote` output. `law_check` (rev-parse) is
   the second site.
2. Premise measured: `git check-ref-format refs/swarm/claims/T-$(touch
   $IFS$MARKER)` is LEGAL — the claim-CAS namespace accepts any legal
   refname (the audit's own claim_orphans note says so). Reading a
   hostile-named claim EXECUTED the payload on the origin host.

**Measured RED** (contract test, fake ssh executing `$SHELL -c
<string as received>`): the marker file was created on the remote side
via `origin_body`. Pre-fix reproduction of the dangerous shape.

Second, local half of the same family (found while testing): sweep's
`tempfile.mkdtemp(prefix=f"inrepo-{task}-")` crashed on a name with
`/` — a hostile name would break the repair path itself.

## Fix (quoting + sanitization only — no thresholds, no verdict history)

- `_ssh_cmd(host, port, *argv)`: every argv element shlex.quote'd into
  the single remote command string, at both exec sites (behavior-
  preserving for legitimate names — byte-identical reads).
- `tempfile_tree`: task name sanitized to `[A-Za-z0-9._-]` for the
  mkdtemp prefix.
