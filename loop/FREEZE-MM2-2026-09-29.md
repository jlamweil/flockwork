## 1. The question, in plain language

When worker A fails a task and worker B corrects it, does B **fix more
tasks when B runs a DIFFERENT model than A** than when B runs the SAME
model? The correction graph can already SHOW cross-model edges (INT-032
window 1 proves ≥1 exists); it cannot say whether those edges are worth
anything. This experiment measures the EDGES' OUTCOMES and the arms'
task-level fix rates.

## 3. What runs (protocol)

1. **Canaries BEFORE any window** (FREEZE-CG §2.5 law): each seat runs
   ONE task, on DIFFERENT tasks, sequentially; both must mint a valid
   `att-mm-<alias>-<role>-<hex6>` archive ref; any failure = abort +
   disclose, no window, no verdict.
2. **Window per arm**: seed the arm origin with the six briefs, start the
   two seats (`SWARM_ORIGIN=<arm origin> python3 l2/inrepo.py worker
   <label>` with the pinned `SWARM_MODEL`, `SWARM_DISPATCH_TIMEOUT=600`,
   `SWARM_HEIR_MAX=1`), let the existing law (heir, reconcile TTL, claim
   races) produce attempts and corrections. No new write machinery.
3. **Close**: when the stream settles (all six tasks fixed or
   heirs-exhausted) or the attempt cap (§6) or wall cap is hit — read out
   via `python3 l2/inrepo.py correction-graph <origin>` and the verdict
   objects. Arm order: **S first, then X** (fixed order, frozen now, so
   the second window can reuse a warmed serve and cannot be reordered
   post hoc).
4. **Provenance pin**: the transcript's model string for every seat is
   recorded in the results file at run time (the freebuff-lesson: never
   attribute a model id we did not verify on the window).
5. **Window discipline**: seat sends happen only inside 17:00–03:00
   (keeper window law); the owner go names the night.

## 4. What's measured (repo alone — the c7/c8 law)

Per attempt, from refs + verdict objects, nothing else:
- `fixed` (the deterministic `verify:` oracle verdict — the outcome unit),
  `oc_rc`, `pytest_rc`;
- the correction edge set from `correction-graph` (who corrects whom,
  each endpoint's model via `mm_model_of`);
- per-attempt wall (claim→verdict commit timestamps).

Derived, per arm and per edge class:
- **Task outcome** (primary): fix rate = tasks `fixed:true` at close ÷ 6,
  at the matched attempt cap.
- **Edge outcome** (mechanism): P(correcting attempt lands `fixed:true` |
  predecessor failed, edge class), where edge class = cross-model
  (endpoint models differ) vs within-model (same model). Arm S has ONLY
  within-model edges by construction; arm X yields both classes.

## 5. Decision rule (frozen)

- **PROVEN (cross-model helps)**: arm X task fix rate exceeds arm S AND
  the Newcombe/Wilson 90% lower bound on the difference is > 0, WITH
  ≥ MIN_N = 5 cross-model correction events observed in arm X.
- **REFUTED**: arm S fix rate ≥ arm X fix rate (i.e. the same-model
  pairing did at least as well) — a real paper finding either way.
- **EDGE-LEVEL support (secondary, reported with either verdict)**: the
  cross-model edge success rate vs the within-model edge success rate,
  MIN_N = 5 per cell for any rate claim; below that, recorded as
  observed-but-unpowered (house MIN_N law — a 4/4 cell stays unproven).
- **NOT-REACHED**: < 5 cross-model correction events in arm X → record
  the base rates honestly, no headline verdict; the paper reports the
  mechanism as unpowered on this stream size.
- **Disclose-discard, thresholds untouched**: infra failures (origin
  unreachable, seat crash, serve death mid-window) are disclosed
  discards; a re-run happens only under THIS freeze; no cherry-picking —
  verdicts cite the FULL closing census of both arms.
- Statistics culture: Wilson LCB90 throughout (accept .70 / agree .75
  heritage, tools/calibration.py); no p-hacking surface exists — every
  number comes from the repo read at close.

## 6. Cost bound (frozen)

- Attempts: hard cap **12 att refs per arm** (6 tasks × 2 seats ×
  (1 + SWARM_HEIR_MAX=1)), **24 total**; at a cap, close and read out.
- Wall: ≤ **6 h per arm**, ≤ 12 h total dispatch (the two windows may
  share a night or split across nights inside the send window).
- Concurrency: exactly **2 seats per arm**, never both arms live at once.
- Accounts/keys: zero new. Seat A and arm S ride the existing MiMo
  endpoint (job 18093231 RUNNING — zero incremental serve cost). Arm X
  adds ONE fleet-served endpoint (roster + GPU·h = the owner call; the
  options table with costs lives in HPC-SERVE-MM2 §1).
- Timeouts: `SWARM_DISPATCH_TIMEOUT=600` s per dispatch, both arms.
- Disk: df-first on every host before anything allocates (DESIGN-NEXT
  §6); arm origins expected ≤ ~100 MB each; abort any step that would
  add > 500 MB.
- The production example-host-a origin and all repo branches stay read-only for
  this run; only swarm refs land on the two arm origins; **no pushes of
  anything to any remote** (DESIGN-NEXT §6).
